## 🌃 Sobre la práctica · El expediente: Prueba-Practica

Este repositorio está destinado a nuestra **prueba práctica de programación en equipo**. Nuestra misión es aplicar conocimientos, desarrollar el razonamiento lógico y construir soluciones claras mediante la colaboración.

Como en una investigación de Gotham, cada dato importa: buscamos analizar el problema, organizar los pasos y comprobar que los resultados tengan sentido.

La investigación de Batman inspira nuestro enfoque: observar los detalles, relacionar la información y comprobar cada hipótesis. Cada ejercicio representa un caso que buscamos entender y explicar con nuestras propias palabras.

> **Lema del equipo:** «Si lo puedes imaginar, lo puedes programar».
>
> Incluso el mejor bati-invento necesita un buen diseño… y unas cuantas pruebas.

La Batseñal pone el ambiente; nuestra tarea es convertir las ideas en pasos claros.

## 🔎 Nuestro proceso · Protocolo de la Baticueva

Este protocolo orienta nuestro trabajo: incluso el mejor detective necesita comprobar sus sospechas.

| Fase | Operación | Objetivo |
| :---: | :--- | :--- |
| **01** | **Investigar · Analizar** | Identificar los datos de entrada, las condiciones y el resultado esperado del problema. |
| **02** | **Preparar · Diseñar** | Organizar una secuencia lógica de solución antes de escribir código. |
| **03** | **Construir · Programar** | Transformar el diseño en instrucciones claras, comprensibles y ordenadas. |
| **04** | **Inspeccionar · Probar** | Revisar casos normales, entradas inválidas y situaciones límite. |
| **05** | **Archivar · Documentar** | Explicar el funcionamiento, las decisiones y lo aprendido para facilitar la revisión. |

> **Regla de la Baticueva:** ningún caso se cierra solo porque «en mi computadora sí funciona».

## ⚡ Filosofía del equipo · Nuestro código de conducta

- **Investigar antes de actuar.** Entender el problema es parte de resolverlo.
- **Prepararse para lo inesperado.** Los casos límite también merecen una prueba.
- **Dejar pistas útiles.** Utilizar variables claras y comentarios que expliquen lo necesario.
- **Mantener la constancia.** Investigar la causa de un error, revisar y ajustar la solución.
- **Proponer con creatividad.** Explorar distintas rutas y evaluar cuál responde mejor al problema.
- **Escribir con claridad.** Pensar en el compañero que leerá el código después.
- **Cuidar al equipo.** Escuchar, preguntar y compartir lo aprendido nos permite avanzar juntos.
- **Aprender de los fallos.** Reconocer los errores para saber qué debemos practicar.

Nuestro cinturón de herramientas empieza con atención, paciencia y disposición para revisar.

## 🦇 Ejercicio 1 · Promedio de calificaciones

### 📋 Descripción

Solicita la cantidad **N de estudiantes** y registra sus calificaciones entre `0` y `10`. Muestra el promedio general, la calificación mayor, la menor y el número de aprobados y reprobados.

### ⚙️ Estructuras sugeridas

`for` para registrar las notas; `while` para validar; condicionales, contadores, acumulador y variables de mayor y menor.

### 🛡️ Validaciones y criterios

N debe ser mayor que cero. Las notas deben estar entre 0 y 10. Se aprueba desde **7/10**.

### 🧪 Casos de prueba propuestos

| Caso | Entrada | Resultado esperado |
| :---: | :--- | :--- |
| **1** | N = 3; notas: 6, 7, 8 | Promedio: 7; mayor: 8; menor: 6; aprobados: 2; reprobados: 1. |
| **2** | N = 1; nota: 0 | Promedio, mayor y menor: 0; aprobados: 0; reprobados: 1. |
| **3** | N = 0 o nota = 11 | Rechazar el dato y volver a solicitarlo. |

## 🦇 Ejercicio 2 · Control de edades con centinela

### 📋 Descripción

Registra edades hasta ingresar **-1**. Determina cuántas personas son menores de edad, adultas y mayores de 65 años, además del promedio de las edades válidas.

### ⚙️ Estructuras sugeridas

`while`, centinela, contadores, acumulador y condicionales.

### 🛡️ Validaciones y criterios

No aceptar edades negativas excepto -1, que termina el ingreso y no se incluye en los cálculos. Para evitar duplicar personas, se consideran menores de 18, adultos de 18 a 65 y mayores de 65. Si no hay registros, no calcular un promedio.

### 🧪 Casos de prueba propuestos

| Caso | Entrada | Resultado esperado |
| :---: | :--- | :--- |
| **1** | 17, 18, 65, 66, -1 | Menores: 1; adultos: 2; mayores de 65: 1; promedio: 41,5. |
| **2** | -1 como primer dato | Finalizar sin registros y sin dividir entre cero. |
| **3** | -5, 20, -1 | Rechazar -5; registrar un adulto; promedio: 20. |

## 🦇 Ejercicio 3 · Calculadora con menú repetitivo

### 📋 Descripción

Presenta un menú con **1) Sumar, 2) Restar, 3) Multiplicar, 4) Dividir y 5) Salir**. Solicita dos números para cada operación y repite el menú hasta seleccionar Salir.

### ⚙️ Estructuras sugeridas

`do-while` para repetir el menú; `switch` para seleccionar la operación; condicionales para validar.

### 🛡️ Validaciones y criterios

Rechazar opciones fuera de 1 a 5 y evitar la división entre cero.

### 🧪 Casos de prueba propuestos

| Caso | Entrada | Resultado esperado |
| :---: | :--- | :--- |
| **1** | Sumar: 8 y 2 | Resultado: 10; mostrar nuevamente el menú. |
| **2** | Dividir: 8 entre 0 | Informar que no se puede dividir entre cero. |
| **3** | Opción 9; luego opción 5 | Rechazar 9 y finalizar al seleccionar 5. |

## 🦇 Ejercicio 4 · Tabla de multiplicar validada

### 📋 Descripción

Solicita un número entero entre **1 y 12**. Si es incorrecto, vuelve a pedirlo. Una vez validado, genera su tabla desde el multiplicador **1 hasta el 12**.

## 🦇 Ejercicio 5 · Cajero universitario

### 📋 Descripción

Gestiona un saldo inicial mediante las opciones **consultar saldo, depositar, retirar, ver número de transacciones y salir**. Actualiza el saldo después de cada operación válida.

### ⚙️ Estructuras sugeridas

`do-while`, selección de opciones, condicionales, acumuladores y contador de transacciones.

### 🛡️ Validaciones y criterios

No permitir valores negativos ni retiros superiores al saldo disponible. Para las pruebas se usa un saldo inicial de $100 y se cuentan como transacciones los depósitos y retiros exitosos.

### 🧪 Casos de prueba propuestos

| Caso | Entrada | Resultado esperado |
| :---: | :--- | :--- |
| **1** | Saldo inicial $100; depositar $50 y retirar $30 | Saldo final: $120; transacciones: 2. |
| **2** | Saldo inicial $100; retirar $150 | Rechazar el retiro; saldo: $100; transacciones: 0. |
| **3** | Depositar -$10 o retirar -$5 | Rechazar los valores sin modificar el saldo ni el contador. |

## 🦇 Ejercicio 7 · Venta de entradas CineCampus

## 🦇 Ejercicio 9 · Matriz lógica de asistencia

### 📋 Descripción

Solicita el número de estudiantes y de días. Para cada estudiante registra **P (presente)** o **A (ausente)** en cada día. Al finalizar, presenta las asistencias y ausencias de cada estudiante y los totales del curso.

## 🦇 Ejercicio 10 · Sistema integrado de ventas

### 📋 Descripción

Integra un menú con **1) Registrar venta, 2) Mostrar estadísticas y 3) Salir**. Cada venta solicita producto, cantidad y precio unitario. Las estadísticas muestran número de ventas, unidades vendidas, total recaudado, venta mayor y promedio por venta.

### ⚙️ Estructuras sugeridas

`do-while` para el menú y `while` para validar; selección, contadores, acumuladores y comparación de la venta mayor.

### 🛡️ Validaciones y criterios

Validar opciones, producto, cantidad entera positiva y precio positivo. Calcular cada venta como cantidad × precio. Si no hay ventas, mostrar cero registros y evitar dividir entre cero.

| **2** | Mostrar estadísticas antes de registrar ventas | Ventas, unidades y total: 0; indicar que aún no hay ventas para calcular mayor y promedio. |

## 🖥️ Ejecución desde un IDE

1. Descargar o clonar este repositorio.
2. Abrir la carpeta del proyecto.
3. Seleccionar el ejercicio que se desea ejecutar.
4. Abrir el archivo `.java`.
5. Verificar que el programa contenga:

```java
public static void main(String[] args)
```

6. Compilar el programa.
7. Ejecutar el archivo.
8. Ingresar los datos solicitados.
9. Revisar los resultados mostrados en consola.

# 🧪 Protocolo de pruebas · Inspección de la Baticueva

Cada programa debe comprobarse utilizando diferentes escenarios antes de considerarlo terminado.

| Tipo de prueba | Objetivo |
| :--- | :--- |
| **Caso normal** | Verificar el comportamiento con valores habituales. |
| **Caso límite** | Comprobar valores mínimos o máximos permitidos. |
| **Entrada inválida** | Verificar que el programa rechace información incorrecta. |
| **Caso especial** | Analizar situaciones que modifican el flujo normal del programa. |

> **Regla de la Baticueva:** ningún caso se cierra únicamente porque «en mi computadora sí funciona».
